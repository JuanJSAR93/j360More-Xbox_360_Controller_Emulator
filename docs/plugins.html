1. Arquitectura y Filosofía del Sistema

El subsistema de plugins de j360More fue diseñado bajo una premisa inquebrantable: máxima estabilidad y cero impacto en la latencia de juego.

1.1. Aislamiento por Procesos Secundarios e IPC TCP

Tradicionalmente, cargar scripts de terceros en el mismo hilo de ejecución de un emulador o interfaz de usuario conlleva el riesgo de que una lectura bloqueante (por ejemplo, esperar datos en un puerto serie COM o un timeout de socket) congele los controles de todos los jugadores o provoque micro-tirones (stuttering).

En j360More:

  • Cada plugin activo se ejecuta en su propio proceso hijo (subprocess.Popen) utilizando el intérprete de Python del entorno virtual dedicado.
  • La comunicación con el núcleo de j360More se realiza a través de un canal IPC ultraligero mediante sockets TCP en la interfaz local (127.0.0.1) con tramas atómicas JSON.
  • El bucle de despacho de mandos virtuales a 120 Hz lee el estado de memoria compartido en microsegundos, asegurando que un retardo físico en el hardware jamás degrade el rendimiento de los demás mandos.
⚡ Garantía de Latencia Cero
Incluso si un microcontrolador Arduino se desconecta físicamente a mitad de una partida y el puerto COM genera un timeout, el proceso principal de j360More seguirá respondiendo a 120 Hz para los demás mandos sin caídas de frames ni congelamientos en Windows.

1.2. Entorno Virtual Automático (.venv)

Para que el usuario final no necesite instalar Python globalmente ni lidiar con la consola:

  • Al abrir la pestaña 🔌 Plugins, j360More verifica la existencia de la carpeta plugins/.venv.
  • Si no existe o faltan dependencias, la interfaz muestra un aviso descriptivo y un botón de un clic: "Instalar Dependencias de Plugins".
  • Para periféricos MIDI se utiliza pygame-ce en lugar de librerías con dependencias C++ nativas no compiladas, garantizando una instalación transparente en cualquier versión de Windows 10 u 11 sin necesidad de Visual Studio Build Tools.

2. Anatomía y Creación de un Plugin desde Cero

Cada plugin reside en su propia carpeta dentro del directorio plugins/. La estructura canónica es la siguiente:

plugins/mi_dispositivo/
Directorio 
plugins/mi_dispositivo/
├── plugin.json         # Manifiesto, esquema UI declarativo y metadatos
├── main.py             # Script principal de lectura y control del hardware
├── requirements.txt    # Librerías pip requeridas (ej: pyserial, pygame-ce)
└── locales/            # (Opcional) Archivos de traducción en.json y es.json

2.1. El Manifiesto (plugin.json)

El archivo plugin.json declara ante el emulador el nombre del plugin, los dispositivos que suministra y sus propiedades:

plugins/mi_dispositivo/plugin.json 
{
  "id": "mi_dispositivo",
  "name": "Mi Dispositivo Físico",
  "version": "1.0.0",
  "author": "Tu Nombre",
  "description": "Controlador físico personalizado para j360More",
  "entry_point": "main.py",
  "devices": [
    {
      "id": "mando_custom",
      "name": "Mando Personalizado",
      "type": "gamepad",
      "num_buttons": 16,
      "num_axes": 6
    }
  ]
}

El emulador lo registrará automáticamente como un periférico seleccionable con el identificador: plugin:mi_dispositivo:mando_custom.

2.2. Ciclo de Vida de Ejecución

  1. Descubrimiento: Al arrancar, PluginManager lee todos los plugin.json.
  2. Arranque: Al iniciar la emulación (o al pulsar "Iniciar" en el panel), j360More ejecuta main.py --port <PORT> --id <PLUGIN_ID>.
  3. Handshake: El script se conecta al socket TCP local mediante PluginDevice.
  4. Bucle de Mapeo: El script muestrea el hardware y llama a device.flush() a alta velocidad.
  5. Cierre Seguro: Al detenerse, device.is_running() se vuelve False y el script libera recursos.

3. Creación de Interfaces Declarativas Personalizadas (UI)

En j360More no necesitas escribir código de interfaz gráfica (Tkinter, PyQt, etc.). Puedes construir ventanas de configuración completas y pestañas personalizadas describiéndolas en formato JSON.

3.1. Diálogo Global de Configuración (global_ui)

Se abre desde el botón ⚙ Configurar en la pestaña de plugins. Admite controles como sliders, checkboxes y menús desplegables estáticos o dinámicos:

3.3. Monitores de Telemetría Dinámicos (progress_bar_multi)

Para animar barras dinámicas en la GUI, define un control progress_bar_multi con las etiquetas que desees:

  • center_zero: false: La barra se llena de 0% a 100% (ideal para pedales y gatillos).
  • center_zero: true: El punto de reposo está centrado al 50% y la barra se expande a la izquierda o derecha (ideal para palancas de stick y ruedas de pitch bend).

En Python, envía eventos de telemetría regulando la tasa a aproximadamente 33 FPS (~30 ms):

main.py (Telemetría a ~33 FPS) 
import time

now = time.perf_counter()
if now - last_telemetry >= 0.03:  # ~33 FPS
    device.send_telemetry({
        "pedals_monitor": [gas_norm, brake_norm, clutch_norm]
    }, pad_id=0)
    last_telemetry = now

4. Soporte Multi-Idioma (i18n)

j360More soporta 7 idiomas oficiales (Español, Inglés, Francés, Portugués, Alemán, Italiano, Ruso). Puedes traducir tus plugins mediante diccionarios inline en plugin.json o carpetas locales/ modulares con archivos es.json y en.json.

5.2. Firmware Arduino C++ Completo (pedals_firmware.ino)

Copia este código y súbelo desde Arduino IDE. Incorpora un filtro digital pasa-bajos exponencial para eliminar el ruido eléctrico (jitter) y envía tramas compactas a 100 Hz:

pedals_firmware.ino 
/*
 * j360More - Firmware para Pedales Físicos USB
 * Velocidad Serial: 115200 baudios (Latencia < 2ms)
 */

const int PIN_GAS    = A0;
const int PIN_BRAKE  = A1;
const int PIN_CLUTCH = A2;
const int PIN_BTN1   = 2;
const int PIN_BTN2   = 3;

// Filtro digital pasa-bajos exponencial para eliminar ruido eléctrico (jitter)
float smoothGas    = 0.0;
float smoothBrake  = 0.0;
float smoothClutch = 0.0;
const float ALPHA  = 0.25; // 0.1 = muy suave, 0.9 = reactivo instantáneo

void setup() {
  Serial.begin(115200);
  while (!Serial && millis() < 3000); // Espera activa segura

  pinMode(PIN_BTN1, INPUT_PULLUP);
  pinMode(PIN_BTN2, INPUT_PULLUP);

  smoothGas    = analogRead(PIN_GAS);
  smoothBrake  = analogRead(PIN_BRAKE);
  smoothClutch = analogRead(PIN_CLUTCH);
}

void loop() {
  // 1. Lectura analógica de 10 bits (0 - 1023)
  int rawGas    = analogRead(PIN_GAS);
  int rawBrake  = analogRead(PIN_BRAKE);
  int rawClutch = analogRead(PIN_CLUTCH);

  // 2. Aplicar filtro pasa-bajos
  smoothGas    = (ALPHA * rawGas)    + ((1.0 - ALPHA) * smoothGas);
  smoothBrake  = (ALPHA * rawBrake)  + ((1.0 - ALPHA) * smoothBrake);
  smoothClutch = (ALPHA * rawClutch) + ((1.0 - ALPHA) * smoothClutch);

  // 3. Lectura de pulsadores digitales (lógica invertida por PULLUP)
  int btn1 = (digitalRead(PIN_BTN1) == LOW) ? 1 : 0;
  int btn2 = (digitalRead(PIN_BTN2) == LOW) ? 1 : 0;

  // 4. Enviar trama compacta optimizada por puerto serie
  // Formato: GAS:val,BRK:val,CLT:val,BTN1:val,BTN2:val\n
  Serial.print("GAS:");
  Serial.print((int)smoothGas);
  Serial.print(",BRK:");
  Serial.print((int)smoothBrake);
  Serial.print(",CLT:");
  Serial.print((int)smoothClutch);
  Serial.print(",BTN1:");
  Serial.print(btn1);
  Serial.print(",BTN2:");
  Serial.println(btn2);

  delay(10); // Despacho a ~100 Hz
}

5.3. Script del Plugin en Python (main.py con pyserial)

El script de Python lee las tramas seriales, reconecta automáticamente si se desenchufa el cable USB y mapea el acelerador y freno directamente a los gatillos RT y LT del mando Xbox virtual:

plugins/arduino_pedals/main.py 
import time
import serial
import serial.tools.list_ports
from plugins.plugin_sdk import PluginDevice

device = PluginDevice(
    id="arduino_pedals",
    name="Arduino Pedals Controller",
    num_buttons=2,
    num_axes=2
)

active_port = "Auto"
baud_rate = 115200
ser = None

def get_best_port():
    for p in serial.tools.list_ports.comports():
        desc = p.description.lower()
        if "arduino" in desc or "ch340" in desc or "cp210" in desc:
            return p.device
    ports = serial.tools.list_ports.comports()
    return ports[0].device if ports else None

def map_axis(val, min_in=50, max_in=950):
    clamped = max(min_in, min(max_in, val))
    return (clamped - min_in) / float(max_in - min_in)

last_telemetry = 0.0

try:
    while device.is_running():
        # Reconexión automática en caliente
        if ser is None or not ser.is_open:
            port = get_best_port() if active_port == "Auto" else active_port
            if port:
                try:
                    ser = serial.Serial(port, baud_rate, timeout=0.02)
                    time.sleep(0.5)
                except Exception:
                    ser = None
                    time.sleep(1.0)
                    continue
            else:
                time.sleep(1.0)
                continue

        try:
            line = ser.readline().decode("ascii", errors="ignore").strip()
            if line:
                data = dict(item.split(":") for item in line.split(",") if ":" in item)
                
                gas_norm = map_axis(int(data.get("GAS", 0)))
                brake_norm = map_axis(int(data.get("BRK", 0)))
                clutch_norm = map_axis(int(data.get("CLT", 0)))

                # Mapeo semántico directo a gatillos Xbox
                device.set_trigger("RT", gas_norm)
                device.set_trigger("LT", brake_norm)
                device.set_button("A", int(data.get("BTN1", 0)) == 1)
                device.set_button("B", int(data.get("BTN2", 0)) == 1)
                device.flush()

                # Telemetría a ~33 FPS para monitores de la GUI
                now = time.perf_counter()
                if now - last_telemetry >= 0.03:
                    device.send_telemetry({
                        "pedals_monitor": [gas_norm, brake_norm, clutch_norm]
                    }, pad_id=0)
                    last_telemetry = now
        except serial.SerialException:
            ser = None

        time.sleep(0.005) # 200 Hz loop
finally:
    if ser and ser.is_open:
        ser.close()

6. Hardware Físico Real 2: Sintetizadores, Pianos y MIDI Pads

Cualquier teclado musical USB, interfaz MIDI o Launchpad físico puede utilizarse para controlar juegos.

6.1. Filtrado de Puertos de Entrada en Windows

En Windows, el subsistema MIDI enumera puertos que son exclusivamente de salida (como Microsoft GS Wavetable Synth). Abrir un puerto de salida en modo lectura causa un error fatal. Por ello, el escaneo debe filtrar siempre is_input == 1:

Filtrado Seguro de Puertos MIDI 
import pygame.midi

pygame.midi.init()
input_devices = []
for dev_id in range(pygame.midi.get_count()):
    interf, name, is_input, is_output, opened = pygame.midi.get_device_info(dev_id)
    if is_input == 1:  # Solo puertos de entrada física
        dev_name = name.decode("utf-8", errors="ignore")
        input_devices.append((dev_id, dev_name))

6.2. Mapeo de Pitch Bend, Modulación y Teclas a Controles de Xbox

Mensaje MIDI Estado Hex Datos Mapeo Recomendado en Xbox 360
Note On 0x90 Tecla/Pad (velocity > 0) Botones A, B, X, Y, LB, RB, D-Pad
Note Off 0x80 Tecla liberada Liberación del botón
Pitch Bend 0xE0 14 bits (0-16383, centro 8192) Stick izquierdo horizontal (LX: -1.0 a +1.0)
Modulation Wheel 0xB0 (CC #1) Valor continuo (0-127) Gatillo derecho (RT: 0.0 a 1.0)
plugins/midi_controller/main.py (Mapeo) 
# Mapeo de Pitch Bend (14-bit) al Stick Izquierdo LX (-1.0 a +1.0)
if status == 0xE0:
    pitch_14bit = (data2 << 7) | data1
    normalized_lx = (pitch_14bit - 8192) / 8192.0
    device.set_stick("LX", max(-1.0, min(1.0, normalized_lx)))
    device.flush()

# Mapeo de Rueda de Modulación (CC 1) al Gatillo Derecho RT (0.0 a 1.0)
elif status == 0xB0 and data1 == 1:
    normalized_rt = data2 / 127.0
    device.set_trigger("RT", normalized_rt)
    device.flush()

# Mapeo de Notas a Botones
elif (status & 0xF0) == 0x90:
    is_pressed = (data2 > 0)
    if data1 == 60:    # Do central (C4) -> Botón A
        device.set_button("A", is_pressed)
    elif data1 == 62:  # Re (D4) -> Botón B
        device.set_button("B", is_pressed)
    device.flush()

7. Referencia Completa del SDK de Python (PluginDevice)

La clase PluginDevice provista en plugins.plugin_sdk abstrae toda la comunicación TCP:

  • device.set_button(name: str, pressed: bool): Asigna botones semánticos ("A", "B", "X", "Y", "LB", "RB", etc.).
  • device.set_trigger(name: str, value: float): Gatillos "LT" y "RT" (rango 0.0 a 1.0).
  • device.set_stick(name: str, value: float): Palancas "LX", "LY", "RX", "RY" (rango -1.0 a 1.0).
  • device.flush(): Envía el paquete atómico TCP al emulador. Debe llamarse al final de cada ciclo.
  • device.on_rumble(callback): Recibe la vibración háptica del juego (small_motor, large_motor) para transmitir a motores de vibración físicos en Arduino.
  • device.send_telemetry(payload, pad_id=0): Envía lecturas en tiempo real a los monitores Canvas.

8. Diagnóstico y Resolución de Problemas

j360More incluye una Consola de Depuración en Vivo dentro de la pestaña 🔌 Plugins que captura todos los print(...) y tracebacks de excepciones de tus scripts.

⚠️ Error COM Ocupado (Errno 13)
Si el log muestra "could not open port 'COMx': PermissionError", asegúrate de haber cerrado el Monitor Serie de Arduino IDE, ya que Windows no permite compartir un puerto COM entre dos programas simultáneamente.
