1. Arquitectura y Filosofía del Sistema

El subsistema de plugins de j360More fue diseñado bajo una premisa inquebrantable: máxima estabilidad y cero impacto en la latencia de juego.

1.1. Aislamiento por Procesos Secundarios e IPC TCP

Tradicionalmente, cargar scripts de terceros en el mismo hilo de ejecución de un emulador o interfaz de usuario conlleva el riesgo de que una lectura bloqueante (por ejemplo, esperar datos en un puerto serie COM o un timeout de socket) congele los controles de todos los jugadores o provoque micro-tirones (stuttering).

En j360More:

  • Cada plugin activo se ejecuta en su propio proceso hijo (subprocess.Popen) utilizando el intérprete de Python del entorno virtual dedicado.
  • La comunicación con el núcleo de j360More se realiza a través de un canal IPC ultraligero mediante sockets TCP en la interfaz local (127.0.0.1) con tramas atómicas JSON.
  • El bucle de despacho de mandos virtuales a 120 Hz lee el estado de memoria compartido en microsegundos, asegurando que un retardo físico en el hardware jamás degrade el rendimiento de los demás mandos.
⚡ Garantía de Latencia Cero
Incluso si un microcontrolador Arduino se desconecta físicamente a mitad de una partida y el puerto COM genera un timeout, el proceso principal de j360More seguirá respondiendo a 120 Hz para los demás mandos sin caídas de frames ni congelamientos en Windows.

1.2. Entorno Virtual Automático (.venv)

Para que el usuario final no necesite instalar Python globalmente ni lidiar con la consola:

  • Al abrir la pestaña 🔌 Plugins, j360More verifica la existencia de la carpeta plugins/.venv.
  • Si no existe o faltan dependencias, la interfaz muestra un aviso descriptivo y un botón de un clic: "Instalar Dependencias de Plugins".
  • Para periféricos MIDI se utiliza pygame-ce en lugar de librerías con dependencias C++ nativas no compiladas, garantizando una instalación transparente en cualquier versión de Windows 10 u 11 sin necesidad de Visual Studio Build Tools.

2. Anatomía y Creación de un Plugin desde Cero

Cada plugin reside en su propia carpeta dentro del directorio plugins/. La estructura canónica es la siguiente:

plugins/mi_dispositivo/
Directorio 
plugins/mi_dispositivo/
├── plugin.json         # Manifiesto, esquema UI declarativo y metadatos
├── main.py             # Script principal de lectura y control del hardware
├── requirements.txt    # Librerías pip requeridas (ej: pyserial, pygame-ce)
└── locales/            # (Opcional) Archivos de traducción en.json y es.json

2.1. El Manifiesto (plugin.json)

El archivo plugin.json declara ante el emulador el nombre del plugin, los dispositivos que suministra y sus propiedades:

plugins/mi_dispositivo/plugin.json 
{
  "id": "mi_dispositivo",
  "name": "Mi Dispositivo Físico",
  "version": "1.0.0",
  "author": "Tu Nombre",
  "description": "Controlador físico personalizado para j360More",
  "entry_point": "main.py",
  "devices": [
    {
      "id": "mando_custom",
      "name": "Mando Personalizado",
      "type": "gamepad",
      "num_buttons": 16,
      "num_axes": 6
    }
  ]
}

El emulador lo registrará automáticamente como un periférico seleccionable con el identificador: plugin:mi_dispositivo:mando_custom.

2.2. Ciclo de Vida de Ejecución

  1. Descubrimiento: Al arrancar, PluginManager lee todos los plugin.json.
  2. Arranque: Al iniciar la emulación (o al pulsar "Iniciar" en el panel), j360More ejecuta main.py --port <PORT> --id <PLUGIN_ID>.
  3. Handshake: El script se conecta al socket TCP local mediante PluginDevice.
  4. Bucle de Mapeo: El script muestrea el hardware y llama a device.flush() a alta velocidad.
  5. Cierre Seguro: Al detenerse, device.is_running() se vuelve False y el script libera recursos.

2.3. Control de Inicio Automático (Activar / Desactivar Plugins al Iniciar)

En j360More puedes decidir si un plugin arranca solo cada vez que abres el emulador o si debe permanecer apagado hasta que lo inicies manualmente:

🔘 Configuración de Inicio desde la GUI

En la pestaña 🔌 Plugins de la ventana de Ajustes:

  • La columna Inicio muestra ✔ Activado o ✖ Desactivado.
  • Al seleccionar un plugin y pulsar ✔ Activar al Inicio o ✖ Desactivar al Inicio, el estado se guarda inmediatamente en config.json ("enabled": false), persistiendo entre reinicios de la aplicación.

📄 Declaración en el Manifiesto (plugin.json)

Puedes definir el comportamiento inicial por defecto agregando "autostart": false en el manifiesto:

plugin.json 
{
  "id": "mi_dispositivo",
  "name": "Mi Dispositivo",
  "autostart": false,
  "entry_point": "main.py"
}

3. Creación de Interfaces Declarativas Personalizadas (UI)

En j360More no necesitas escribir código de interfaz gráfica (Tkinter, PyQt, etc.). Puedes construir ventanas de configuración completas y pestañas personalizadas describiéndolas en formato JSON. El motor de renderizado (plugins/plugin_ui_renderer.py) se encarga de crear los componentes visuales nativos y sincronizarlos bidireccionalmente con tu proceso de Python.

3.1. Catálogo Completo de Controles UI

A continuación se detallan todos los controles visuales soportados, sus parámetros, cómo se declaran en plugin.json y cómo se gestionan en Python:

1. Deslizador Numérico (slider)

Barra deslizante analógica (ttk.Scale) con indicador dinámico de valor numérico entero en tiempo real.

  • id (string): Identificador único del campo.
  • label (string o dict i18n): Texto visible en la interfaz.
  • min (número, defecto 0) y max (número, defecto 100): Rango del deslizador.
  • default (número): Valor inicial.
  • step (número, opcional): Incremento por paso.
plugin.json & Python Handler 
// 1. En plugin.json:
{
  "id": "gas_deadzone",
  "label": { "es": "Zona Muerta Acelerador (%)", "en": "Gas Deadzone (%)" },
  "type": "slider",
  "min": 0,
  "max": 40,
  "default": 5
}

# 2. En main.py:
@device.on_field_change("gas_deadzone")
def on_deadzone_changed(new_val, pad_id):
    device.log(f"Zona muerta actualizada para mando {pad_id}: {new_val}%")

2. Interruptor Booleano (checkbox)

Casilla de verificación estándar (ttk.Checkbutton) para habilitar o deshabilitar opciones booleanas.

  • id (string): Identificador único.
  • label (string o dict i18n): Texto explicativo.
  • default (boolean): Estado inicial (true o false).
plugin.json & Python Handler 
// En plugin.json:
{
  "id": "invert_brake",
  "label": { "es": "Invertir Polaridad Freno", "en": "Invert Brake Polarity" },
  "type": "checkbox",
  "default": false
}

# En main.py:
@device.on_field_change("invert_brake")
def on_invert_brake(is_inverted: bool, pad_id: int):
    device.log(f"Inversión de freno: {is_inverted}")

3. Menú Desplegable Estático (dropdown)

Selector de opciones de solo lectura (ttk.Combobox) con lista estática de opciones.

  • id (string): Identificador único.
  • label (string o dict i18n): Título del selector.
  • options (lista de strings): Opciones disponibles.
  • default (string): Valor por defecto.
plugin.json & Python Handler 
// En plugin.json:
{
  "id": "baud_rate",
  "label": { "es": "Velocidad Serial", "en": "Serial Baud Rate" },
  "type": "dropdown",
  "options": ["9600", "57600", "115200"],
  "default": "115200"
}

# En main.py:
@device.on_field_change("baud_rate")
def on_baud_change(new_baud_str, pad_id):
    active_baud = int(new_baud_str)

4. Menú Desplegable Dinámico con Escaneo en Vivo (dynamic_dropdown)

Desplegable interactivo acompañado de un botón 🔄 que consulta a tu plugin en caliente para descubrir puertos físicos conectados (COM o MIDI) y actualiza el menú en tiempo real sin reiniciar la aplicación.

  • discovery_action (string): Nombre de la acción registrada en Python que se ejecuta al pulsar 🔄.
  • device.update_field_options(field_id, options): Método del SDK para refrescar las opciones en pantalla.
plugin.json & Python Handler 
// En plugin.json:
{
  "id": "midi_port",
  "label": { "es": "Puerto MIDI Físico", "en": "Physical MIDI Port" },
  "type": "dynamic_dropdown",
  "discovery_action": "scan_midi_ports",
  "options": ["AUTO"],
  "default": "AUTO"
}

# En main.py:
@device.on_action("scan_midi_ports")
def handle_scan(pad_id: int):
    import pygame.midi
    found = ["AUTO"]
    for i in range(pygame.midi.get_count()):
        info = pygame.midi.get_device_info(i)
        if info and info[2] == 1:  # Solo puertos de entrada física
            found.append(f"{i}: {info[1].decode('utf-8')}")
    device.update_field_options("midi_port", found)

5. Botón de Acción (button)

Botón de comando (ttk.Button) para invocar rutinas específicas como auto-calibración en cero o reinicio de hardware.

  • id (string): Identificador único.
  • label (string o dict i18n): Texto del botón.
  • action (string, opcional): Nombre de la acción a disparar (por defecto coincide con id).
plugin.json & Python Handler 
// En plugin.json:
{
  "id": "btn_zero_cal",
  "label": { "es": "Calibrar Centro en Cero", "en": "Calibrate Center Zero" },
  "type": "button",
  "action": "zero_calibrate"
}

# En main.py:
@device.on_action("zero_calibrate")
def on_zero_calibrate(pad_id: int):
    device.log(f"Centro calibrado correctamente para mando {pad_id}")

6. Monitores de Telemetría Dinámicos (progress_bar_multi y progress_bar_pair)

Monitor interactivo dibujado sobre un lienzo tk.Canvas oscuro. Incluye barras individuales con código de colores, texto dinámico de porcentaje (0% a 100%) y nombres de canal personalizados.

  • bars (entero): Número de barras paralelas (ej. 2 o 3).
  • labels (array de strings): Nombres de cada barra (ej. ["GAS", "FRENO", "CLUTCH"]).
  • center_zero: false: La barra se llena de 0% a 100% (ideal para pedales y gatillos).
  • center_zero: true: Reposo en el 50% y expansión bidireccional izquierda/derecha (ideal para joysticks y pitch bend).
  • Frecuencia recomendada: Enviar telemetría a aproximadamente 33 FPS (~30 ms) para mantener la GUI completamente fluida.
plugin.json & Python Streaming 
// En plugin.json:
{
  "id": "pedals_monitor",
  "type": "progress_bar_multi",
  "label": { "es": "Recorrido Físico de Pedales", "en": "Pedals Physical Travel" },
  "bars": 3,
  "labels": ["GAS", "FRENO", "CLUTCH"],
  "center_zero": false
}

# En main.py:
import time

now = time.perf_counter()
if now - last_telemetry >= 0.03:  # ~33 FPS
    device.send_telemetry({
        "pedals_monitor": [gas_norm, brake_norm, clutch_norm]
    }, pad_id=1)
    last_telemetry = now

3.2. Contenedores de Diseño: global_ui vs pad_ui_customization

El sistema provee dos ubicaciones estratégicas para renderizar tu interfaz:

A. Diálogo de Configuración Global (global_ui)

Se declara en la raíz de plugin.json y se abre mediante el botón ⚙ Configurar de la lista de plugins. Es ideal para parámetros del puerto COM, baudios o selección de periféricos físicos que afectan al plugin en general.

B. Pestañas Personalizadas por Mando (pad_ui_customization)

Inserta pestañas personalizadas dentro del panel de cada mando virtual (Mando 1, Mando 2, etc.):

  • disable_default_tabs: Array de strings con los identificadores exactos de las sub-pestañas nativas que deseas ocultar porque no aplican a tu periférico físico.
    Identificador String Sub-pestaña Nativa Ocultada Cuándo utilizarlo / Casos de uso
    "sticks" Sticks / Palancas Analógicas (Calibración de sticks izquierdo LX/LY y derecho RX/RY, zonas muertas y curvas) Dispositivos sin palancas analógicas como pedaleras de carreras, volantes puros, guitarras o botoneras arcade.
    "triggers" Gatillos / Triggers (Calibración analógica de recorrido, umbrales y zonas muertas de gatillos traseros LT y RT) Controles sin gatillos analógicos, como joysticks de aviación clásicos, palancas de lucha retro o teclados simples.
    "rumble" Vibración / Force Feedback (Ajuste de intensidad y prueba de motores hápticos de alta y baja frecuencia) Periféricos que no disponen de motores físicos de vibración excéntrica o actuadores hápticos.
    "general" General / Mapeo de Botones (Asignación de botones A, B, X, Y, LB, RB, D-Pad, Start, Back, Guide) Periféricos dedicados que reemplazan todo el mapeo estándar por su propia interfaz de calibración personalizada.

    Ejemplos típicos: Para pedaleras: ["sticks", "rumble"]. Para arcade fight sticks digitales: ["triggers", "sticks"]. Para teclados MIDI: ["sticks", "rumble"].

  • custom_tabs: Array de pestañas que contienen sections (agrupaciones visuales ttk.LabelFrame) con sus respectivos fields.

4. Soporte Multi-Idioma (i18n)

El sistema de plugins cuenta con un motor de internacionalización nativo (plugins/plugin_i18n.py) integrado con el selector de idioma global de j360More. Permite que tus diálogos de configuración, nombres de dispositivos, pestañas personalizadas, opciones de menús y monitores de telemetría se adapten al idioma del usuario sin requerir código complejo ni reiniciar el emulador.

4.1. Arquitectura y Códigos de Idioma Admitidos

El motor de traducción normaliza y soporta oficialmente los siguientes códigos de idioma:

Código Idioma Nota de Normalización
"es" Español Idioma predeterminado del emulador. Utilizado como base principal de respaldo (fallback).
"en" English Idioma internacional secundario de fallback.
"fr" Français Francés estándar.
"pt_BR" Português (Brasil) Se normaliza automáticamente si se especifica como "pt", "pt-br", "pt_br" o "pt-BR".
"de" Deutsch Alemán estándar.
"it" Italiano Italiano estándar.
"ru" Русский Ruso (soporte completo de caracteres cirílicos UTF-8 sin restricciones).

Cascada de Respaldo Inteligente (Fallback)

Si el usuario ejecuta j360More en un idioma no traducido en tu plugin (por ejemplo, Alemán de), el sistema busca en de → si falta, busca en es → si falta, busca en en → si ninguna coincide, muestra la primera disponible. La interfaz nunca falla ni lanza excepciones por falta de una traducción.

4.2. Método 1: Enfoque Inline (Dentro de plugin.json)

  • "name" y "description" del plugin y de devices[].
  • "global_ui.title" y "fields[].label".
  • "labels" en progress_bar_multi (diccionario de listas de nombres de barra).
  • "options" en desplegables (como objetos con "value" técnico y "label" traducible).
  • "custom_tabs[].title" y "sections[].name".

5.2. Firmware Arduino C++ Completo (pedals_firmware.ino)

Copia este código y súbelo desde Arduino IDE. Incorpora un filtro digital pasa-bajos exponencial para eliminar el ruido eléctrico (jitter) y envía tramas compactas a 100 Hz:

pedals_firmware.ino 
/*
 * j360More - Firmware para Pedales Físicos USB
 * Velocidad Serial: 115200 baudios (Latencia < 2ms)
 */

const int PIN_GAS    = A0;
const int PIN_BRAKE  = A1;
const int PIN_CLUTCH = A2;
const int PIN_BTN1   = 2;
const int PIN_BTN2   = 3;

// Filtro digital pasa-bajos exponencial para eliminar ruido eléctrico (jitter)
float smoothGas    = 0.0;
float smoothBrake  = 0.0;
float smoothClutch = 0.0;
const float ALPHA  = 0.25; // 0.1 = muy suave, 0.9 = reactivo instantáneo

void setup() {
  Serial.begin(115200);
  while (!Serial && millis() < 3000); // Espera activa segura

  pinMode(PIN_BTN1, INPUT_PULLUP);
  pinMode(PIN_BTN2, INPUT_PULLUP);

  smoothGas    = analogRead(PIN_GAS);
  smoothBrake  = analogRead(PIN_BRAKE);
  smoothClutch = analogRead(PIN_CLUTCH);
}

void loop() {
  // 1. Lectura analógica de 10 bits (0 - 1023)
  int rawGas    = analogRead(PIN_GAS);
  int rawBrake  = analogRead(PIN_BRAKE);
  int rawClutch = analogRead(PIN_CLUTCH);

  // 2. Aplicar filtro pasa-bajos
  smoothGas    = (ALPHA * rawGas)    + ((1.0 - ALPHA) * smoothGas);
  smoothBrake  = (ALPHA * rawBrake)  + ((1.0 - ALPHA) * smoothBrake);
  smoothClutch = (ALPHA * rawClutch) + ((1.0 - ALPHA) * smoothClutch);

  // 3. Lectura de pulsadores digitales (lógica invertida por PULLUP)
  int btn1 = (digitalRead(PIN_BTN1) == LOW) ? 1 : 0;
  int btn2 = (digitalRead(PIN_BTN2) == LOW) ? 1 : 0;

  // 4. Enviar trama compacta optimizada por puerto serie
  // Formato: GAS:val,BRK:val,CLT:val,BTN1:val,BTN2:val\n
  Serial.print("GAS:");
  Serial.print((int)smoothGas);
  Serial.print(",BRK:");
  Serial.print((int)smoothBrake);
  Serial.print(",CLT:");
  Serial.print((int)smoothClutch);
  Serial.print(",BTN1:");
  Serial.print(btn1);
  Serial.print(",BTN2:");
  Serial.println(btn2);

  delay(10); // Despacho a ~100 Hz
}

5.3. Script del Plugin en Python (main.py con pyserial)

El script de Python lee las tramas seriales, reconecta automáticamente si se desenchufa el cable USB y mapea el acelerador y freno directamente a los gatillos RT y LT del mando Xbox virtual:

plugins/arduino_pedals/main.py 
import time
import serial
import serial.tools.list_ports
from plugins.plugin_sdk import PluginDevice

device = PluginDevice(
    id="arduino_pedals",
    name="Arduino Pedals Controller",
    num_buttons=2,
    num_axes=2
)

active_port = "Auto"
baud_rate = 115200
ser = None

def get_best_port():
    for p in serial.tools.list_ports.comports():
        desc = p.description.lower()
        if "arduino" in desc or "ch340" in desc or "cp210" in desc:
            return p.device
    ports = serial.tools.list_ports.comports()
    return ports[0].device if ports else None

def map_axis(val, min_in=50, max_in=950):
    clamped = max(min_in, min(max_in, val))
    return (clamped - min_in) / float(max_in - min_in)

last_telemetry = 0.0

try:
    while device.is_running():
        # Reconexión automática en caliente
        if ser is None or not ser.is_open:
            port = get_best_port() if active_port == "Auto" else active_port
            if port:
                try:
                    ser = serial.Serial(port, baud_rate, timeout=0.02)
                    time.sleep(0.5)
                except Exception:
                    ser = None
                    time.sleep(1.0)
                    continue
            else:
                time.sleep(1.0)
                continue

        try:
            line = ser.readline().decode("ascii", errors="ignore").strip()
            if line:
                data = dict(item.split(":") for item in line.split(",") if ":" in item)
                
                gas_norm = map_axis(int(data.get("GAS", 0)))
                brake_norm = map_axis(int(data.get("BRK", 0)))
                clutch_norm = map_axis(int(data.get("CLT", 0)))

                # Mapeo semántico directo a gatillos Xbox
                device.set_trigger("RT", gas_norm)
                device.set_trigger("LT", brake_norm)
                device.set_button("A", int(data.get("BTN1", 0)) == 1)
                device.set_button("B", int(data.get("BTN2", 0)) == 1)
                device.flush()

                # Telemetría a ~33 FPS para monitores de la GUI
                now = time.perf_counter()
                if now - last_telemetry >= 0.03:
                    device.send_telemetry({
                        "pedals_monitor": [gas_norm, brake_norm, clutch_norm]
                    }, pad_id=0)
                    last_telemetry = now
        except serial.SerialException:
            ser = None

        time.sleep(0.005) # 200 Hz loop
finally:
    if ser and ser.is_open:
        ser.close()

6.3. Script Completo y Ejecutable del Plugin MIDI (main.py)

A continuación se presenta el código fuente completo, probado y listo para producción del plugin MIDI (plugins/midi_controller/main.py), con decodificación de eventos, soporte de reconexión, escaneo dinámico y telemetría en tiempo real:

plugins/midi_controller/main.py 
"""
plugins/midi_controller/main.py
Controlador de Teclado y Pads MIDI Físicos para j360More.
"""

import sys
import os
import time

sys.path.insert(0, os.path.abspath(os.path.join(os.path.dirname(__file__), "../..")))
from plugins.plugin_sdk import PluginDevice

# 1. Instanciación del dispositivo con 8 botones semánticos y 4 ejes
device = PluginDevice(
    id="midi_controller",
    name="Controlador MIDI USB",
    num_buttons=8,
    num_axes=4
)

# Mapeo de notas MIDI estándar a botones de Xbox 360
NOTE_MAP = {
    60: "A",       # C4 (Do central)
    62: "B",       # D4 (Re)
    64: "X",       # E4 (Mi)
    65: "Y",       # F4 (Fa)
    67: "LB",      # G4 (Sol)
    69: "RB",      # A4 (La)
    71: "START",   # B4 (Si)
    72: "GUIDE",   # C5 (Do agudo)
}

active_midi_port = "AUTO"
velocity_threshold = 15

# -------------------------------------------------------------
# Callbacks de Interfaz UI
# -------------------------------------------------------------

@device.on_action("scan_midi_ports")
def handle_scan_midi_ports(pad_id: int):
    """Escanea puertos de entrada física y actualiza el combobox."""
    found = ["AUTO"]
    try:
        import pygame.midi
        if not pygame.midi.get_init():
            pygame.midi.init()
        for i in range(pygame.midi.get_count()):
            info = pygame.midi.get_device_info(i)
            if info and info[2] == 1:  # Filtrar estrictamente solo puertos de entrada
                dev_name = info[1].decode("utf-8", errors="ignore")
                found.append(f"{i}: {dev_name}")
    except Exception as e:
        device.log(f"Error escaneando MIDI: {e}", "ERROR")

    device.update_field_options("midi_port", found)
    device.log(f"Puertos MIDI detectados: {found}")

@device.on_field_change("midi_port")
def handle_port_change(new_port, pad_id):
    global active_midi_port
    active_midi_port = str(new_port)
    device.log(f"Puerto MIDI seleccionado: {active_midi_port}")

@device.on_field_change("velocity_threshold")
def handle_velocity_change(new_val, pad_id):
    global velocity_threshold
    velocity_threshold = int(new_val)
    device.log(f"Umbral de velocidad: {velocity_threshold}")

# -------------------------------------------------------------
# Bucle de Control y Lectura a 120 Hz
# -------------------------------------------------------------

def run_loop():
    import pygame.midi
    if not pygame.midi.get_init():
        pygame.midi.init()

    pg_midi_in = None
    target_id = None

    if active_midi_port != "AUTO" and ":" in active_midi_port:
        try:
            target_id = int(active_midi_port.split(":")[0])
        except ValueError:
            target_id = None

    if target_id is None:
        for i in range(pygame.midi.get_count()):
            info = pygame.midi.get_device_info(i)
            if info and info[2] == 1:
                target_id = i
                break

    if target_id is not None:
        try:
            pg_midi_in = pygame.midi.Input(target_id)
            device.log(f"Conectado a dispositivo MIDI #{target_id}")
        except Exception as e:
            device.log(f"No se pudo abrir MIDI #{target_id}: {e}", "ERROR")
    else:
        device.log("Esperando conexión de teclado MIDI...", "WARN")

    last_velocity_norm = 0.0
    last_pitch_norm = 0.5  # Centro neutro (50%)
    last_mod_norm = 0.0
    last_telemetry_time = 0.0

    try:
        while device.is_running():
            t0 = time.perf_counter()

            if pg_midi_in and pg_midi_in.poll():
                midi_packets = pg_midi_in.read(16)
                for packet in midi_packets:
                    data, timestamp = packet
                    status, d1, d2, _ = data
                    cmd = status & 0xF0

                    # 1. Note On / Note Off
                    if cmd == 0x90 and d2 > 0:
                        if d2 >= velocity_threshold:
                            btn = NOTE_MAP.get(d1)
                            if btn:
                                device.set_button(btn, True)
                            device.set_button_index(d1 % 8, True)
                            last_velocity_norm = d2 / 127.0
                    elif cmd == 0x80 or (cmd == 0x90 and d2 == 0):
                        btn = NOTE_MAP.get(d1)
                        if btn:
                            device.set_button(btn, False)
                        device.set_button_index(d1 % 8, False)

                    # 2. Pitch Bend Wheel (14 bits)
                    elif cmd == 0xE0:
                        pitch_14bit = (d2 << 7) | d1
                        norm_stick = max(-1.0, min(1.0, (pitch_14bit - 8192) / 8192.0))
                        device.set_stick("LX", norm_stick)
                        last_pitch_norm = (norm_stick + 1.0) / 2.0

                    # 3. Modulation Wheel (CC #1)
                    elif cmd == 0xB0 and d1 == 1:
                        norm_trigger = max(0.0, min(1.0, d2 / 127.0))
                        device.set_trigger("RT", norm_trigger)
                        last_mod_norm = norm_trigger

                device.flush()

            if last_velocity_norm > 0:
                last_velocity_norm = max(0.0, last_velocity_norm - 0.04)

            now = time.perf_counter()
            if now - last_telemetry_time >= 0.03:
                last_telemetry_time = now
                device.send_telemetry({
                    "midi_telemetry": [last_velocity_norm, last_pitch_norm, last_mod_norm]
                }, pad_id=0)

            elapsed = time.perf_counter() - t0
            sleep_time = 0.0083 - elapsed
            if sleep_time > 0:
                time.sleep(sleep_time)

    finally:
        if pg_midi_in:
            try:
                pg_midi_in.close()
            except Exception:
                pass
        pygame.midi.quit()
        device.log("Dispositivo MIDI cerrado limpiamente.")

if __name__ == "__main__":
    device.start(run_loop)

7. Referencia Completa del SDK de Python (PluginDevice)

La clase PluginDevice (ubicada en plugins/plugin_sdk.py) encapsula todo el protocolo IPC de bajo nivel, la gestión de memoria protegida por hilos (threading.Lock) y la comunicación por sockets TCP JSON locales con el motor de j360More.

7.1. Inicialización y Ciclo de Vida

__init__(id: str, name: str, num_buttons: int = 16, num_axes: int = 6)
Constructor principal. Inicializa los búferes internos de botones semánticos, ejes y disparadores.

  • id (str): Identificador único (debe coincidir con devices[].id en plugin.json).
  • name (str): Nombre descriptivo visible para el usuario en la GUI.
  • num_buttons (int): Cantidad de botones físicos indexados (0..N-1).
  • num_axes (int): Cantidad de ejes analógicos indexados (0..N-1).

is_running() -> bool
Indica si el proceso de emulación y el socket IPC permanecen activos. Debe ser la condición principal del bucle while.

set_connected(is_connected: bool, device_id: Optional[str] = None)
Notifica explícitamente a j360More sobre la conexión o desconexión del cable físico. Si se pasa False, invoca reset_inputs() automáticamente para evitar entradas pegadas y marca el dispositivo como [Offline] en la GUI.

is_device_connected() -> bool
Devuelve True si el dispositivo físico está marcado como conectado y operativo.

reset_inputs(flush: bool = False)
Restablece de inmediato todos los botones a False, gatillos a 0.0 y palancas a 0.0 en memoria.

report_devices(devices: List[Dict[str, Any]])
Registra o actualiza dinámicamente ante j360More una lista de periféricos conectados en caliente sin esperar a que el emulador pregunte.

start(loop_fn: Optional[Callable[[], None]] = None)
Punto de entrada de ejecución del plugin. Parsea argumentos CLI (--ipc-port, --ipc-host, --simulate), realiza el handshake e inicia el bucle en el hilo principal.

import time
from plugins.plugin_sdk import PluginDevice

# Declarar dispositivo con 12 botones físicos y 4 ejes analógicos
device = PluginDevice(id="flight_stick", name="Flight Stick HOTAS", num_buttons=12, num_axes=4)

def run_loop():
    device.log("Iniciando lectura de joystick indexado a 120 Hz.", "INFO")
    while device.is_running():
        # 1. Normalizar los 4 canales analógicos crudos al rango [-1.0, 1.0]
        device.set_axis(0, 0.0)    # Eje 0: Alerones (centro)
        device.set_axis(1, 0.5)    # Eje 1: Elevador (+50%)
        device.set_axis(2, 0.0)    # Eje 2: Timón de cola (centro)
        device.set_axis(3, -0.8)   # Eje 3: Acelerador (-80%)

        # 2. Leer estado de los 12 pulsadores físicos
        for btn_idx in range(12):
            device.set_button_index(btn_idx, btn_idx in (0, 3))

        # 3. Transmisión atómica de todos los índices al emulador
        device.flush()
        time.sleep(0.0083) # ~120 Hz

if __name__ == "__main__":
    device.start(run_loop)

7.4. Sincronización y Transmisión de Estados

flush()
Empaqueta de forma atómica y segura (threading.Lock) todos los cambios acumulados de botones, gatillos y palancas y los envía al emulador por TCP. Debe llamarse al final de cada iteración de lectura.

send_telemetry(data: Dict[str, Any], pad_id: int = 1)
Transmite datos numéricos en vivo a los monitores Canvas (progress_bar_multi) de la GUI. Se recomienda regular su envío a ~33 FPS (cada 30-33 ms) para evitar saturar el hilo de interfaz.

update_field_options(field_id: str, options: List[Any])
Actualiza dinámicamente las opciones de un combobox (dropdown o dynamic_dropdown) en la GUI sin recargar.

set_field_value(field_id: str, value: Any, pad_id: int = 1)
Fuerza un nuevo valor visual en un widget de la GUI (útil tras rutinas automáticas de centrado).

log(message: str, level: str = "INFO")
Imprime un mensaje en stdout y lo retransmite simultáneamente a la Consola de Depuración de Plugins integrada en j360More. Niveles válidos: "INFO", "WARN", "ERROR", "DEBUG".

main.py (Bucle a 120 Hz + Telemetría Regulada a 33 FPS) 
import time
from plugins.plugin_sdk import PluginDevice

device = PluginDevice(id="pedales_pro", name="Pedales de Competición")

def run_loop():
    last_telemetry = 0.0
    telemetry_interval = 0.033  # ~33 FPS para no saturar la GUI

    device.log("Driver iniciado a 120 Hz con telemetría regulada.", "INFO")

    while device.is_running():
        t_start = time.perf_counter()

        gas_norm, brake_norm = 0.85, 0.10

        # 1. Enviar entradas de control al emulador a 120 Hz
        device.set_trigger("RT", gas_norm)
        device.set_trigger("LT", brake_norm)
        device.flush()  # Envío atómico inmediato por socket TCP

        # 2. Enviar telemetría visual regulada para monitores de la GUI
        now = time.perf_counter()
        if now - last_telemetry >= telemetry_interval:
            last_telemetry = now
            device.send_telemetry({"monitor_barras": [gas_norm, brake_norm, 0.0]}, pad_id=1)

        # 3. Mantener cadencia de 120 Hz (8.33 ms)
        elapsed = time.perf_counter() - t_start
        sleep_rem = 0.00833 - elapsed
        if sleep_rem > 0:
            time.sleep(sleep_rem)

if __name__ == "__main__":
    device.start(run_loop)

7.5. Decoradores de Eventos Bidireccionales

@device.on_rumble
Firma: callback(small_motor: float, large_motor: float)
Se ejecuta cada vez que el juego envía vibración háptica XInput hacia el mando emulado (0.0 a 1.0) para transmitirla a motores físicos en Arduino o volantes con force feedback.

@device.on_field_change(field_id: str)
Firma: callback(new_value: Any, pad_id: int)
Se dispara inmediatamente cuando el usuario mueve un slider, alterna un checkbox o selecciona una opción del combobox en la interfaz.

@device.on_action(action_name: str)
Firma: callback(pad_id: int)
Se ejecuta cuando el usuario presiona un botón (button) o el botón de refresco 🔄 de un menú desplegable dinámico (discovery_action).

@device.on_discover_devices
Firma: callback() -> List[Dict[str, Any]]
Permite registrar dispositivos adicionales provistos dinámicamente ante el gestor de plugins.

main.py (Integración de los 4 Decoradores) 
from plugins.plugin_sdk import PluginDevice

device = PluginDevice(id="volante_ffb", name="Volante Force Feedback")

# 1. Rumble / FFB desde el juego
@device.on_rumble
def handle_rumble(small_motor: float, large_motor: float):
    device.log(f"FFB -> Pesado: {int(large_motor*255)}, Ligero: {int(small_motor*255)}", "DEBUG")

# 2. Cambios en Widgets de la GUI
@device.on_field_change("sensibilidad")
def on_sens_change(new_val, pad_id: int):
    device.log(f"Sensibilidad ajustada a {new_val}% en Mando {pad_id}")

# 3. Acciones de Botón en la GUI
@device.on_action("calibrar_centro")
def on_calibrar(pad_id: int):

    device.log(f"Centro calibrado a cero para Mando {pad_id}.")

# 4. Descubrimiento Dinámico de Periféricos
@device.on_discover_devices

    return [{"id": "volante", "name": "Volante FFB", "num_buttons": 12, "num_axes": 4}]

if __name__ == "__main__":
    device.start()

8. Gestión de Conexión, Desconexión y Reconexión en Caliente (Hot-Plug)

En periféricos de juego y simuladores físicos (pedales, volantes, cajas de cambio o teclados MIDI), un tirón accidental del cable USB o una micro-desconexión no debe congelar el emulador ni dejar entradas trabadas (*stuck inputs*) acelerando indefinidamente.

8.1. Los Dos Niveles de Enlace: IPC vs Hardware Físico

El sistema de j360More separa estrictamente la capa de comunicación de software de la capa de conexión física de hardware:

🌐 Nivel 1: Enlace IPC Local

Socket TCP local entre main.py y j360More. Si el proceso termina o se cae, el servidor detecta el cierre, pone el plugin en stopped y limpia los mandos virtuales al instante.

🔌 Nivel 2: Enlace Físico de Hardware

Cable USB/COM o MIDI entre el dispositivo físico y main.py. Si se desenchufa el cable, el script Python sigue vivo, por lo que debe detectar la desconexión e informar a j360More.

main.py (Desacoplamiento IPC Nivel 1 vs Enlace Físico Nivel 2) 
# Nivel 1 (IPC): El socket con j360More permanece vivo aunque se caiga el cable USB
while device.is_running():
    if hardware_serial is not None:
        try:
            # Nivel 2: Lectura física sobre el cable USB
            line = hardware_serial.readline().decode().strip()
            device.set_trigger("RT", float(line) / 1023.0)
            device.flush()
        except Exception as err:
            # Falla de cable en Nivel 2: Notificar a j360More vía Nivel 1
            device.log(f"Pérdida de enlace físico USB: {err}", "WARNING")
            try: hardware_serial.close()
            except: pass
            hardware_serial = None
            device.set_connected(False)
    else:
        time.sleep(1.0) # Esperar reconexión física

8.2. Prevención de Entradas Pegadas (Stuck Inputs)

Si un jugador pisa el pedal a fondo (RT: 1.0) y el cable USB se desconecta, sin una gestión adecuada el emulador retendría ese 1.0 en memoria para siempre. Para evitarlo:

  • device.reset_inputs(flush=True): Restablece de forma atómica todos los botones a False y ejes a 0.0 en memoria.
  • device.set_connected(False): Neutraliza automáticamente las entradas, notifica al emulador el evento device_status y en la GUI el mando pasa a mostrar la etiqueta [Offline].
main.py (Prevención de Stuck Inputs: Vulnerable vs Seguro) 
# ❌ INCORRECTO: VULNERABLE A ENTRADAS TRABADAS (STUCK INPUTS)
try:
    raw = ser.readline()
    device.set_trigger("RT", int(raw) / 1023.0) # 1.0 (a fondo)
    device.flush()
except Exception:
    pass  # ¡ERROR! Si el cable se suelta, RT queda congelado en 1.0 indefinidamente


# ✅ CORRECTO: PROTECCIÓN TOTAL CON RESET_INPUTS Y SET_CONNECTED
try:
    raw = ser.readline()
    device.set_trigger("RT", int(raw) / 1023.0)
    device.flush()
except Exception as e:
    device.log(f"Cable USB desconectado: {e}", "WARNING")
    # 1. Neutraliza controles a 0.0 / False en memoria
    # 2. Envía snapshot neutro por IPC al emulador
    # 3. Notifica a la GUI que el mando está [Offline]
    device.set_connected(False)
    device.reset_inputs(flush=True)

8.3. Patrón de Auto-Reconexión en Caliente No Bloqueante

Tu script nunca debe abortar ni colapsar si el puerto no está listo o si el cable se desconecta. Implementa un intento periódico no bloqueante:

Patrón de Reconexión USB Hot-Plug 
import time, serial
from plugins.plugin_sdk import PluginDevice

device = PluginDevice(id="pedales", name="Pedales USB")
serial_conn = None

def try_connect() -> bool:
    global serial_conn
    try:
        serial_conn = serial.Serial("COM3", 115200, timeout=0.01)
        device.set_connected(True)  # Informa a j360More: Hardware activo
        device.log("Hardware USB conectado en COM3.", "INFO")
        return True
    except Exception:
        serial_conn = None
        return False

def run_loop():
    global serial_conn
    last_reconnect = 0.0

    if not try_connect():
        device.set_connected(False)
        device.log("Dispositivo offline. Escuchando conexión física...")

    while device.is_running():
        if serial_conn:
            try:
                line = serial_conn.readline().decode("utf-8").strip()
                if line:
                    procesar_trama(line)
                    device.flush()
            except Exception as e:
                device.log(f"Desconexión física: {e}", "WARNING")
                try: serial_conn.close()
                except: pass
                serial_conn = None
                device.set_connected(False)  # ¡Neutraliza entradas de inmediato!
                last_reconnect = time.time()
                continue
        else:
            # Reintentar cada 1.5s sin bloquear el bucle
            now = time.time()
            if now - last_reconnect >= 1.5:
                last_reconnect = now
                if try_connect():
                    continue
            time.sleep(0.02)

9. Diagnóstico y Resolución de Problemas

j360More incluye una Consola de Depuración en Vivo dentro de la pestaña 🔌 Plugins que captura todos los print(...) y tracebacks de excepciones de tus scripts.

⚠️ Error COM Ocupado (Errno 13)
Si el log muestra "could not open port 'COMx': PermissionError", asegúrate de haber cerrado el Monitor Serie de Arduino IDE, ya que Windows no permite compartir un puerto COM entre dos programas simultáneamente.
